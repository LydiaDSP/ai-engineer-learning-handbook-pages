Databricks 怎样给 Agent 一份可分叉的工作环境？

为数据管道、会话、记忆和工作文件保留同一个起点，让不同分支独立验证各自的假设。

Databricks · 技术团队成员（MTS）约 17 分钟演讲中文导读与讲解 · Lila
环境分叉数据管道团队记忆
导入

两路调查怎样从同一个现场出发

每天的订单汇总突然对不上。数据工程师可能先查重复入库，也可能先查上游字段是否缺失。两路调查如果共用同一套可写表、缓存和笔记，先跑完的一组就可能改变另一组的输入。Ankit Mathur 用这样的数据管道问题解释，Agent 团队需要一份可以分叉的工作环境。各分支从同一个状态出发，在各自的环境里测试假设，再把证据交给人或负责汇总的 Agent。

讲者从国际象棋说起。棋局可以复制，尝试一条路线之后，下一条仍能从原局面开始。数据管道的局面包括数据、执行环境和当前调查进度。为了让验证有意义，先确定哪些状态要跟着分支走，以及结果回来以后由谁复核。

数据管道

把测试所需的表、计算和权限一起准备好

只切一个 Git 分支，代码有了副本，数据和计算仍可能指向同一套服务。Ankit 指出，就连生产读取也可能消耗共享资源，写入还可能因重跑产生重复结果。Databricks 的案例把数据表、计算和治理设置一起分叉，让 Agent 能在各自的环境里修改并重跑管道，比较不同修复的结果。

每条分支应有可核对的起点和结果。记录基线版本、输入数据、实际改动、输出差异和运行状态。如果修复必须跨到另一个服务，而那个服务没有可隔离的测试版本，就在报告里写清验证覆盖到哪里。主线负责人据此决定是否需要补测。

记忆

分支可以继承调查进度，团队记忆仍需整理

演讲里，Postgres 保存会话状态。新分支可以继承已有对话，后续回复留在各自分支。Agent 的笔记和此前对话的总结也可以进入记忆库。Databricks 用离线算力整理这些记录，让另一个 Agent 标出冲突，再把归并后的信息提供给团队检索。

某条笔记可能只对一个版本、一个数据集或一条调查路线成立。先留在本地分支，等复跑或人工核对后，再判断它能否进入团队记忆。例如，「这份测试数据的订单号会重复」应附样本和版本。团队如果要新增规则，还要确认真实业务里能否只靠订单号去重。

运行环境

让会话、文件和数据从同一个状态分叉

讲者以 Neon 为例解释存储层。计算和存储分开，数据库分支可以引用共同的历史。分支发生写入时，各自保留改动。这个做法称为写时复制。演讲还讲到，Agent 往往把脚本、笔记和测试产物写在工作目录里，所以文件系统也需要分叉。Databricks 同步本地和远端存储，让另一个沙箱能基于已有工作文件继续执行。

沙箱分叉后，检查三件事。两条分支是否确实拿到同一版初始状态，后续写入是否分别记账，挂载与权限是否把实验限在各自的环境内。讲者也把这种结构用于并行事故调查。排查分支可以保留各自的观察记录，汇总方再比较来源和证据。

上手

用两份本地副本测试订单汇总差异

在测试目录里做一次小实验。设业务规则是每天每个订单只计一次，金额以已确认的上游对账表为准。准备一个导入样本 o1,100、o2,200、o2,200、o3,空值。独立对账样本给出 o3=300，因此正确输出是三笔订单，共 600。

  1. 固定起点。保存样本和聚合逻辑的基线。把输入、脚本和一份简短的调查笔记复制进 A、B 两个目录，每边只写自己的输出目录。
  2. 并行验证。A 只验证重复导入，记录去重键和被消除的行数。B 只验证缺失金额，用独立对账样本补值，记录来源、匹配键和仍未匹配的行。两边都跑相同的订单数、金额和空值检查。
  3. 比较证据。A 的去重能把行数降到三行，仍有一项缺失金额。B 可以补齐金额，但仍多计一次 o2。各自交回改动说明和输出，让接手人知道哪项检查通过、哪项仍失败。
  4. 重跑组合修复。从同一基线另开一份副本，复核两种改动能否一起使用。确认三笔、600、无空值，再重跑一次，记录结果和原样本是否发生改动。
完成标准

另一位同事能用基线复跑两条路线，定位每条路线排除的原因，并用同样的检查复核组合修复。

练习

检查分支隔离和证据能否交接

两个 Agent 分别检出代码，为什么验证仍会互相影响？

它们可能读写同一个测试表，共享计算配额或者覆盖同一个输出文件。核对各分支实际连接的数据、计算和输出位置。用一条写入后的检查确认另一分支和基线仍保持原状。

分支 A 写下「按订单号去重」，能立刻写进团队记忆吗？

先附这次样本、业务口径和可复跑的检查。确认真实数据在同一订单下会不会有多笔需要保留的记录，再决定把它保留为这次调查笔记，还是加入经过审核的团队规则。

两个分支都完成了运行，可以直接采用它们的结论吗？

展开参考分析

对比相同验收条件和基线，确认各自通过哪些检查。合并思路时再开一份分支验证组合结果，避免一项修复掩盖另一项问题。演练中，只有组合结果同时满足三笔、600、无空值。
