Simon Willison 回顾 2026 年大模型的三个转折

从日常编程、长时间探索到游戏试玩，三个案例各自用什么证据验证结果？

独立开发者 · Datasette 创作者约 19 分钟演讲中文导读与讲解 · Lila
编程 Agent长任务试玩验证
导入

同一项任务，什么时候值得交给 Agent？

Simon Willison 用三个亲身经历回顾这一年。编程 Agent 进入他的日常工作，带工具的模型能反复尝试一个较长的任务，最后是游戏从能跑起来到让他愿意继续玩。三个转折点对应的是他用这些工具做成了什么。

每个例子的验收方式不同。写代码可以跑测试，找蜂鸣声可以打开纸箱检查，游戏是否好玩要回到实际试玩。把验收方式说清楚，才能从演示的印象走到下一次可重复的尝试。

编程

把编程 Agent 用进日常工作

Willison 把第一个转折点放在 2025 年 11 月。他说，Claude Opus 4.5 和 GPT-5.1 带来的改善足以改变使用频率，编程 Agent 开始进入每天的工作。他用生成骑自行车的鹈鹕来观察模型变化，早期几个例子里的自行车仍有明显结构问题。不同任务仍要各自验证。

到后来的鹈鹕演示，模型已经能交出更像样的图。围绕同一道题公开展示的次数越多，越需要换一题或加一个新的要求，检验能力能否迁移。Willison 用骑独轮车的火烈鸟举例，说明可以怎样换题。随后展示的是 Jeff Dean 分享的几种动物和交通工具组合。

长任务

先定义目标、工具和现场验收

第二个转折点是讲者所称的“Fable 级模型”。按他的用法，如果任务可行、目标明确，工具也准备好了，模型就能多次尝试直至取得可验证的结果。这个说法来自他的使用经验。

找蜂鸣声时，目标是把四十多个纸箱里的声音定位到一个可检查的范围内。Willison 提供了家中的手机、平板和电脑，Agent 找到声源定位的参考论文并实现工具。工具将候选范围缩到约 41 厘米。他随后打开纸箱，找到了一个旧的一氧化碳探测器。

换到工作中的任务，先写出 Agent 能观察到的证据，以及最后由谁确认。演讲还回顾了模型安全事件。把工具接入长任务时，应为本轮限定可访问的数据、可执行的动作和停止条件。正文对相关事件保留讲者归属和已有的防护概述。

试玩

把“好玩”拆成能试玩的问题

Willison 用同一个浣熊游戏点子试了几次。模型做出了不同版本，他自己各玩了一分半就停了。在另一个即时战略游戏项目里，他请模型改善体验。从讲者的记录看，这次运行约 12 小时，模拟约 1,000 局，引入了额外争夺目标和新的反馈，最终他觉得游戏更好玩。

模拟局能核对胜负条件、僵局和策略分布。实际试玩还能查清玩家是否读懂目标、是否愿意再来一局。演讲的第三个转折点来自他的试玩感受，这些具体信号可以用来设计你自己的检查。

回顾

用新的目标检验工具能做多远

演讲结尾回到一个变化：交给 Agent 的日常工作越多，讲者就越常遇到需要定义目标、比较方案和确认结果的任务。他回看年初预测，也提到自己感受到的职业冲击，用“Deep Blue”指模型做到了自己原来擅长的工作时产生的感受。

读这段回顾时，可以把公开事件、厂商主张和讲者亲测的案例分开理解。模型能否稳定完成你手头的任务，仍要用你能观察和复查的结果判断。

上手

让 Agent 迭代一个本地小游戏

选一个两分钟内能结束的小原型，例如用键盘移动角色、在 30 秒内收集五个标记。准备一个可打开的基线版和两张地图。第二张在做改动时留给最后一次复测。

  1. 先玩基线。记录能否看懂目标、首次得分花了多久、计时结束后能否重开。
  2. 每轮改一个问题。让 Agent 读到可复现的描述，例如“进入游戏后找不到目标，直到倒计时快结束才第一次得分”。允许它在本地改一个提示或反馈，保留改动前的版本。
  3. 重跑检查并换地图。在相同地图并排试玩两版，再换新地图。验证得分、结算、重开都照常。请一位朋友首次试玩两版，记录是否不经提醒就懂目标。

验收记录至少写清试了哪个版本、看到了什么、是否愿意保留改动。程序能检查规则，主观体验由试玩者确认。

练习

用三道题复核验收方式

如果 Agent 只报告“做完了”，还要查看什么？

打开实物产出，按事先写明的通过条件核对。小游戏要完整跑一次开局、得分、结算和重开。

很多模拟局都能结束，可以判断游戏好玩了吗？

这些记录说明规则在所测场景下可以走完。再让实际玩家试玩，记录他们能否读懂目标，以及是否愿意重开或推荐给别人。

为什么最后要换一张地图复测？

改动可能只对熟悉的路线奏效。新地图可以查出目标提示是否普遍清晰，以及原来通过的规则是否出现回归。
