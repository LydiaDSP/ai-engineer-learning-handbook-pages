学习手册 07 / Zach Bruggeman

Ramp 怎样让同事接得上 Agent 做过的事？

Zach Bruggeman 从一次 Inspect 排障和 ReviewBuddy 的诞生，讲共享会话、验证记录和统一工具怎样改变 Ramp 的工程协作。

Ramp · Principal 软件工程师（大会介绍）约 15 分钟演讲中文导读与讲解 · Lila
协作编程共享会话验证证据
导入

一次报错让更多同事加入了排障。

Ramp 的工程师 Andrew 报告 Inspect 出了问题，Zach Bruggeman 就请 Inspect 调查自己。Agent 怀疑刚接好的监测代码，负责开发的人最初也不信这个判断。讨论留在团队频道里，Dylan 可以追问，Andrew 可以补充线索，后来加入的人也看得到这条判断怎样变成了补丁。

Inspect 是 Ramp 的协作编程 Agent，会话在远程运行，团队可以从 Inspect、Slack 或 Linear 接入。讲者说，演讲时 Ramp 约 75% 的代码由 Inspect 编写并交付。这个自报占比描述了它在公司内部的使用情况，演讲没有解释如何计数，也未用它衡量生产率。

上手

用一项小改动练习从 Agent 交接给同事。

选一项团队允许共享、能在测试环境复现的小改动，例如修好筛选结果为空时的提示。请一位没有参与过程的同事复核。交接完成时，同事应能找到对应改动，复跑一项检查并写明下一步。

  1. 立约。在工单写下复现步骤、期望表现和测试环境。把团队可读的 Agent 会话连到工单。
  2. 留证据。让 Agent 在测试分支完成改动。记录 PR 与提交、改动前后的截图和复验步骤。实际只跑了一条路径，也照样写清覆盖范围。
  3. 做交接。在工单贴出改动、证据和待办。让同事先自行阅读，再从指定提交复验。把对方缺失的信息补回原工单。
  4. 做一次迁移。下次开同类工单时，复制经过复核的记录结构，让第二位同事直接接手。
请为这项改动整理一份团队交接记录。
写明原问题、期望状态、PR 与提交编号。
按顺序列出实际执行过的检查，并附可以打开的结果。
标明当前未知项以及接手者可以独立完成的下一步。

完成标准 同事能从记录定位正确的提交，复跑至少一项检查，区分已验证与待验证的范围，并把结果回填工单。

共享

常用工具和新发现从哪里传给团队？

Zach 算了一笔很小的账。每个人单独花十五分钟配置工具，乘上几百人的规模，组织就花掉了好几天。工具和做法持续更新，配置也会反复做。Ramp 给全公司提供同一个 Inspect，接上遥测、数据库等内部工具。某种用法被证明通用时，团队可以更新同一个入口，让后来使用的人直接受益。各人仍可保留自己的工作方式。

讲者说，Inspect 会话默认在公司内部可见。同事可以在日常频道里看到某个难题怎样被拆开，也可以请 Inspect 从已有会话梳理同事的用法。Inspect 团队观察到新的用法后，再判断是否补内置能力、工具或数据。

评审

把评审者要用的证据和 PR 放在一起。

评审者打开 PR 时，可以沿着共享会话查看原始对话、Agent 用了什么工具、改动前后的截图，或验证 Agent 在浏览器里操作的录屏。对话交代问题缘由，工具记录能查实际运行的检查，截图和录屏能回看指定环境中的可见行为。接手者还能据此找出未覆盖的路径。

练习时可以从一条最容易复验的用户路径起步。给截图加上对应提交和测试步骤，评审者才知道自己看到的是哪一版、怎样重跑。对权限或数据行为的判断，要用相应的测试结果或可查询状态支持。

排障

同一个讨论串里，怀疑怎样变成可检验的判断？

Inspect 当时已经能读 Datadog，自身的监测却刚加好。它说问题出在监测代码。Zach 和 Dylan 都有疑虑，Dylan 便让它检查遥测库，看看问题是否早就存在，只是以前观测不到。

Inspect 随后定位到更具体的现象。按讲者回忆，用于 Cloudflare Workers 的 OpenTelemetry 库调用了 fetch，响应体没有被读取或取消。团队请 Inspect 给导出器做了补丁，显式取消响应体。Zach 说部署后当时没有再看到同类报错。同一个频道保留了从怀疑、追问到观察补丁效果的过程，最早报错的 Andrew 也能继续参与。

复用

ReviewBuddy 从哪一项已有能力开始？

Ramp 曾经换过几款现成的代码审查工具。Daniel 和 Frangel 发现，Inspect 已有多来源的自动化触发能力，其中一个入口是在 PR 创建时触发。两人重用这个入口，做出了内部审查 Agent ReviewBuddy。这次尝试也促使 Inspect 团队思考如何把编写和审查接起来。

拿这段经历对照自己的团队，可以先找一种每周都在重复的交接。把一个已经存在的事件和一项明确的检查连起来，例如 PR 打开后提醒作者补上复现步骤。先让作者和评审者判断提示是否有用，再决定是否扩展到更多仓库。

练习

用三种交接卡点检验记录。

同事打开 PR，只看到一张截图，能核验哪些内容？

展开参考分析

截图能看出当时的页面呈现。请作者补上所在环境、对应提交、操作路径和预期表现。需要确认其他路径或权限行为时，再找能覆盖那些要求的证据。

Agent 说监测代码导致故障，下一条问题可以怎么问？

展开参考分析

请它标出相关日志、对应调用和发生条件，列出另一种能解释同一现象的原因。做小范围改动后，沿同一条路径观察错误是否再现，记录验证范围。

团队想复用一个人的 Agent 用法，先检查什么？

展开参考分析

看同事能不能打开这份会话和必要的证据，能不能在相同权限下复跑步骤，哪些输入依赖个人配置。确认通用的部分之后，再放进工单模板、共享工具或平台默认配置。
