导读

Agent 找到命令以后，还得自己给结果做减法

Ayush Bhardwaj 在改一个查旧会话的 CLI 时发现，Agent 调用工具后经常再筛一遍结果。一次调用只需查文档里的一个设置，Agent 先下载整页，再就地过滤到 40 行。另一次调用只要依赖报告的总数，便截取末尾的 40 行。他从这些已经发生的运行来判断，哪些能力应该进入工具。

其中一个隐蔽的例子是测试明明失败，管道末段却顺利退出。Agent 可能得到绿色状态，又读不到筛掉的错误行。读这一篇时可以检查自己的 CLI，先选一个需要 Agent 反复加工结果的命令。让调用时能够表达它究竟要找哪一项，再比较新旧工作流是否还答得出同样的问题。

读完可以做什么
  • 发现多余过滤带来的实际成本
  • 让失败在退出状态和输出里都能看见
  • 从保留下来的调用里拿一组可复测的验收题
上手

把从测试日志找失败信息改成工具自带能力

教学例：本地测试命令生成长日志，工程师经常需要第一段有用错误和失败用例名。用一条成功、一条断言失败、一条编译错误及一条输出为空的记录作输入。输出紧凑摘要和可读的完整日志定位。

第 1 步

先将命令行为留下来

从失败中学习之前，需要知道早先环境如何捕捉它。

展开可复制的提示词
在固定测试夹具上保存原始命令、标准输出、错误输出与退出状态。对照人工答案，写清这条调用最后要哪个字段、需要全文的部分在哪里。

完成标志　每份输入都能指出真实状态与预期摘要。截断的输出列出保留范围。

第 2 步

让错误有独立的可读位置

一条绿色管道不能单独说明前面的测试通过了。

展开可复制的提示词
在包装器保存真正测试进程的退出状态。先输出含失败类别、失败位置和日志路径的短摘要，再按需返回完整日志。安排一个故意失败的样例核对状态，以及在 Bash 管道中截取输出的状态。

完成标志　真正失败的命令仍返回失败。摘要锁定故障，不使用“没有看到错误”充当成功条件。

第 3 步

用选择项表达需求

给字段、范围和批量能力，比让 Agent 反复写筛选器更容易验收。

展开可复制的提示词
新增按用例名选择的选项与机器可读摘要格式。保留默认的人类输出。准备两个匹配、零匹配、未知参数和多个日志 ID 的例子，文档写出何时退回完整日志。

完成标志　合法输入返回对应记录，零匹配和命令失败的含义不同。版本说明中不存在已经无实际效果的指令。

第 4 步

用没见过的问题检验改动

降低 token 或轮数要与完成情况一起测量。

展开可复制的提示词
用同一批保留测试比较新版与旧版。每组记录回答能否指出失败位置、能否定位完整原文、总轮数、成本和用时，保留不一致的输出。

完成标志　找到更短的输出时仍能答对问题。遇到未减少总成本的失败，能指出是重复运行还是信息不够又得取日志。

第 1 节

Agent 怎样绕开难用的输出

从自己的会话里找一条重复管道，看前一个命令给出了什么，后一个命令保留了什么。顺着这个关系就能看到工具缺的选项。

回看这一节 · 01:46:46 ↗

演讲报告了约两万次工具调用的样本，其中约四分之一在输出之后接过滤。这个比例来自讲者样本，实际产品要自己查代表性的任务。在自己的日志中可先分类命令：某类读操作长期接着筛相同的字段，适合把前移过滤做到工具里；每次筛选项都不同的场景，可以先提供结构明确、能用脚本处理的数据。

第 2 节

失败应该被输出和状态同时表达

一个被截短的测试日志仍需要回答两件事。测试是成功还是失败，失败的原始证据在哪里。

回看这一节 · 01:49:01 ↗

在 Bash 未设置 pipefail 的情况下，管道常由最后一个命令的状态代表整体。后面的截断工具读到了几行就顺利退出，也可能仍得到绿灯，而测试本身已经失败。团队可以让包装器在适当环境保持正确的失败状态，把摘要放到调用者看得到的位置。需要测试“真的失败”的情形；仅在无故障样本上得到绿色无法检验整个管道。

第 3 节

把三个常见绕行改进 CLI

选择内容、精简字段和批量读取解决的是三种不同的问题。输出一律缩短，仍会让调用方重新猜哪些行重要。

回看这一节 · 01:51:29 ↗

Bhardwaj 把命中周围的内容做成可选范围，紧凑格式让每个结果用较小容量表达。他还发现旧选项已经改成空操作，模型仍跟着 Skill 文本传入参数。改变接口后可以重放已有示例，检查“推荐用法”有没有继续要求不存在的能力。

第 4 节

用真实命令做回放和验收

先留一组用来发现问题的调用，再留一组用来判断修复是否有用。两组都看答案和轮次，别只看输出字数。

回看这一节 · 01:54:28 ↗

讲者举的 DuckDB 案例里，Agent 模式将模型读取的工具输出缩短 59%，省下的量约占模型总读取 token 的 0.5%。成本和运行时间没有改善。可以分别记录命令一次返回的长度和完成任务所需的总消耗，还要查结果是否足以作答。如果第一次返回只剩一行却看不出对应文件，额外检索会把下一轮的消耗加回来。

用这一讲的方法做一次小练习

实作。找出自己常用 CLI 后面重复出现的一种裁剪，写一个原生命令选项。

展开参考答案

描述它要选的记录和字段，给出被省略信息的取回方式。保留出错时的状态和日志位置，并更新帮助和示例。

实作。为“测试失败却显示绿色”准备一个可复现的验收用例。

展开参考答案

让一条测试命令确实失败，再让下游过滤命令成功结束。对照记录两个退出状态、摘要和完整错误，验证调度程序能收到真实失败。

理解检查。限长输出与匹配周边消息解决的是同一个问题吗？

展开参考答案

限长规定总量。匹配周边消息按任务相关性选内容，可以让 Agent 找回需要的上下文。

理解检查。压缩了输出，为什么还测答题与轮次？

展开参考答案

字符变少可能只占调用成本很小的一部分。压缩也可能删掉关键内容，导致多调一次工具或答错。
