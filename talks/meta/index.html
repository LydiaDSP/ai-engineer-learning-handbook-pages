导入

一组轮值为什么需要一位共享的 AI 队友？

凌晨两点同时响了 12 个告警，值班员得先决定查什么。Meta 团队用一个教学场景说明，结账延迟、支付客户端超时、配置变更和历史事故的记录本来就存在。难点在于这些记录分散在各自的工具里，值班员要一次次提问，再把答案凑成一条时间线。

讲者提出为每组轮值配置一位持续工作的 AI 队友。它先关联告警、工单、近期变更和既有处理记录，把待验证的判断、证据和待审批的缓解方案带到值班员面前。团队共用执行记录和交接记忆。演讲中的节省时间场景用于说明流程，讲者提出下一步再严格测量实际省下多少时间。

上手

用一组模拟告警跑一次值班交接。

以只读方式演练。准备四条模拟记录，包含 01:49 支付客户端超时阈值变更、01:51 支付超时告警、01:52 结账 P99 延迟告警、02:00 报表磁盘容量告警。再加一条过去事故记录，其中同类变更曾影响支付。

  1. 分组。把支付和结账放入一个待验证的事件组，单列报表磁盘告警，写清两组的优先级依据。
  2. 写出验证办法。将配置变更、支付超时和结账延迟按时间排序。对照受影响区域与对照区域的超时率，并核查是否有同期变更。
  3. 提出缓解方案。把建议提交值班负责人，附受影响范围、预期恢复指标、观察窗口和需要重新评估的条件。演练中由同事扮演审批人。
  4. 写一条交接。交代已检查的证据、仍在核实的判断、下一步和接手人。让同事仅凭交接找到原始记录，再补一条对判断的校正。
只用随附的模拟记录进行分诊。
按时间列出证据，标出可能相关的告警及分组依据。
给出一条可检验的假设和一项只读检查，说明什么结果会改变你的判断。
写出待批准的缓解建议及验收指标。最后生成下一班能接手的交接摘要。

完成标准 接手同事能用原始记录复核分组和时间线，指出一项待验证判断，并说出由谁决定是否采取缓解措施。

分诊

先把零散信号放进一条可查的时间线。

讲者用告警脚本、工单机器人、部署机器人和历史事故库解释上下文为什么会断开。单个入口只保留自己看到的东西。持续运行的队友能把多个信号带进同一轮调查，并把普通工单、测试失败、事件调查或知识检索发给适合的 Agent。团队也能接入自己已有的 Agent、Skills 和手册。

在结账案例中，配置推送发生在告警之前，相似历史事故提供了调查线索。提交给值班员的是假设、可复核的证据和下一步。写调查记录时，应分别标明时间顺序、已查过的记录和还缺的证据。

授权

按操作风险和检验难度逐级授权。

Meta 团队借用新工程师进入轮值的过程设计了三级自主权。第一阶段只读调查。第二阶段可以拟修复、给测试计划、跟进 CI 和评审，由人批准后才进入生产。第三阶段可处理经验证的低风险事项，比如归并重复事项或关闭噪声告警。高关键性决策仍交给值班员，代码变更走团队原有的评审和 CI。

授权的单位是某一类操作。讲者考虑出错代价和错误能否通过测试、CI 或评审被及时发现，也要求先看 Agent 在这类操作上的历史表现。把这一原则写进值班表时，可为每类操作记录可读信息、可执行范围、通过条件和审批人。

交接

每天值班的人会换，证据和决定要传下去。

团队共享工作台，聊天工具和事件处理界面也能继续查询同一条工作。使用合成数据的晨间摘要示意把 23 件事写成 3 件待人决策、18 件已处理、2 件处理中。需要处理的事项直接说明要决定什么，并附调查结论和修复草稿。系统还会定期检查卡住或失败的自动化运行，尝试恢复，遇到无法处理的情况通知人。

讲者还展示了跨班次记忆。上一班的 Sam 纠正一条结账故障的处理经验，下一班的 Jordan 可以查到记录及其来源。每组轮值有独立的身份、权限、配置和记忆。系统跟踪记忆实际是否有用，再决定哪些经验值得保留。交接里的历史经验可以指向手册或事故记录，下一班就能检查它是否仍适合当前场景。

评估

用审批质量和人员负担判断能否扩大授权。

讲者观察到值班员更常从一条待核验假设开始，也表示要用更严格的研究测量值班负担。使用次数只描述有没有人在用。团队试跑时，可以一起记录人均调查用时、每班被打断次数、需要重做的调查以及缓解提案通过评审的比例。

中等关键性工作属于他们计划验证的下一步。这个学习样例以模拟记录做分诊和交接，把缓解操作留给审批人，方便先检验调查材料能否支持一次可靠决策。

练习

用三道题复核分诊结果和授权边界。

支付超时和结账延迟接连发生，该如何分组？

展开参考分析

先归入同一个待验证组，依据是时间相近且支付处在结账路径上。查监控和同期变更，确认异常是否发生在同一范围。报表磁盘告警先单列，直至有证据表明相关。

Agent 很擅长关闭噪声告警，可以顺便批准配置回滚吗？

展开参考分析

关闭噪声告警的历史表现仅支持原操作的权限。配置回滚会改变生产状态。让 Agent 附上变更前后指标、受影响范围和回滚后观察条件，由负责人审批。

下一班拿到一条旧故障经验，要怎样决定是否采用？

展开参考分析

查经验的来源、当时适用的服务范围以及当前手册和指标。保留当前检查结果。如果旧结论已失效，把最新依据和适用条件补回交接记录。
