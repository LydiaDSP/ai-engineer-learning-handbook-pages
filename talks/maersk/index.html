导读

一次把项目重写干净，为什么几周后又改不动了？

Dmitry Buykin 曾删去一批旧测试和代码。代码变少了，少数业务仍依赖的分支也一起消失。原先不断长出例外和重复实现的工作方式还在，复杂度很快超过人能理解的范围。这场分享从一笔已经审批的订单切入。看清谁能判定这笔订单该走哪条路，比先安排 Agent 重写整套实现更有用。

演讲里的系统同时服务多个流程和国家。两个看起来重复的分支可能来自不同市场的要求。专家能确认规则含义，工程师能追到规则使用的事实，测试能反复证明一部分行为。每周只动一个证据足够的小范围，团队才有机会看清维护有没有越过业务边界。

读完可以做什么
  • 找出一条自然语言业务规则的事实来源、决策者和执行边界。
  • 将一次专家纠错变成能在旧版和新版之间重放的案例。
  • 依据覆盖和使用记录决定哪些分支适合封装或退役。
上手

用一个已经审批的订单练习改规则

教学场景使用虚构的订单和审批规则。挑一个国家和一个订单流程，约定低于上限时自动受理，超限时必须审批，金额或权限不明时转人工。只在本地模拟，不连接真实订单系统。

第 1 步

先把业务决定写清楚

“询问团队”可能是去查额度，也可能真要负责人决定。

展开可复制的提示词
把规则拆为输入事实、条件、输出、责任人。用低于上限、刚好等于上限、超过上限和额度未知四类样本追问。边界没有依据时标为待专家确认。

完成标志　事实与决定分列。团队明确谁有资格处理刚好等于上限的情况。

第 2 步

找到重复动作的归属

工具封装固定步骤以后，旧说明如果仍要求同样动作，执行者可能做两遍。

展开可复制的提示词
画出当前的查额度、选择分支、写入和确认路径。为每个动作指定唯一执行者，列出改动后仍需保留的人工决定。标记已经由工具完成的旧说明。

完成标志　每个写入动作只有一个责任方；遇到不明金额时没有默认放行。

第 3 步

用同一批订单跑旧版与新版

真实输入可以把路径涉及的问题留在证据里。

展开可复制的提示词
根据已经去标识的样本编写本地回放。对照新版与旧版的决定、操作序列和最终结果。若不存在可重放的超限样本，就明确报告该分支缺证据。

完成标志　构造漏掉审批的变体时，检查会报错；修好后再跑一次才能变绿。

第 4 步

给这次改动留下交接

历史虽然有用，下一班只需要先读到当前有效状态。

展开可复制的提示词
输出准备交给下一位维护者的当前规则、有效市场范围、已覆盖案例、尚未覆盖分支和下一次核对人。将试错过程放进单独的历史记录。

完成标志　下一位维护者能区分仍有效的限额和已被撤销的试验。

先把每周的维护缩到人能检查的范围

第 2 节

用同一份规则服务专家与 Agent

典型分工是把稳定步骤交给程序，把业务判断保存在专家看得懂的地方。先观察执行轨迹，可以知道哪些步骤已经稳定到适合做成工具。

回看这一节 · 00:03:17 ↗

编程 Agent 修改的是工作说明，运行时 Agent 按说明办订单，某个国家的变化不一定适用于邻国。规则文档可以同时承担两种交接。结构区域让执行者读取字段和分支，相邻的人类说明解释为什么有例外、谁确认和最早何时适用。直接让一个模型从零整合这些信息，容易把用途不同的两段话合并成一个命令。

第 3 节

把重复操作收进工具

只把流程封装进工具还不够。原指令如果重复写着工具已经内置的动作，Agent 可能继续做一遍。迁移时要同时维护规则的边界。

回看这一节 · 00:06:04 ↗

教学推演。假设新工具已经包含按批次写入和确认回执，但旧提示还说“确认后再次写入”。开发 Agent 要把说明收进工具，最小验收单就要证明两件事。已有审批的样本只执行一次写入。尚未审批的样本不能从任何路径进入写入。两项同时成立，才能知道工具封装没有把原保护丢掉。

第 4 节

把专家反馈变成新的评测

平台需要保存业务反馈、定位相关范围和给出关闭证据。否则每一件疑问最终都要绕回最熟悉系统的那个人。

第 5 节

真任务回放决定哪些东西该留

重放用来检验行为有无变化，真实使用记录则用来决定一个旧变体还有没有保留价值。两个证据回答的是不同问题。

回看这一节 · 00:13:08 ↗

讲者约 13:34 提到先写下什么结果会推翻改动，并让新检查故意失败一次。约 14:02，他用同一批冻结的真实任务比较旧版与新版。第二个 Agent 按清单独立复核，只看证据，不接收作者的推理过程。

重放本来就不能穷尽所有历史。演讲里，每周先看真实用到的选项，再判断长时间未访问的变体是否可以退出。每个决定都需要记录范围。一条路径没出现在回放中，可能因为样本不够，也可能因为市场已撤销这个功能。前者应该补证据，后者才适合准备退役。

练习

用这一讲的方法做一次小练习

一条“超过金额上限时请与团队确认”的规则，怎样拆出可复用的工具和人工步骤？

展开参考答案

先让程序从权威记录取金额与额度。用专家维护的分支表说明什么情况下必须找负责人审批，模型选择分支，工具负责执行已经获批的写入。

准备把一套文字规则改成工作流，怎样发现重复执行？

展开参考答案

记录改动前后同一批任务的操作序列。若工具已写入而旧指令还要求写入，重放应暴露重复动作。删除重复步骤，并单独检查审批决定仍然存在。

新旧结果差异为零，但没有任何样本超额，你会怎样报告？

展开参考答案

已覆盖的分支一致。超额分支缺真实回放证据，应补充代表性样本并验证它确实要求人工批准。

一条变体在旧测试里存在，却长期未使用，怎样安全退役？

展开参考答案

先核对使用记录和业务负责人，保存退役理由和受影响范围，再一起处理变体和专属测试。其余路径继续用真实样本复验。
