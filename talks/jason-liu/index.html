学习手册 第二天 01 / Jason Liu

学会判断什么值得做，以及什么算做好

从摄影、界面设计到架子鼓，Jason Liu 用自己的练习说明，AI 把执行门槛压低之后，人可以怎样扩大目标并提高判断力。

OpenAI · Developer Experience约 19 分钟演讲中文导读与讲解 · Lila
创作判断产品设计跨领域学习
导读

“交互有点钝”要改哪一处

Jason Liu 在艺术学校学设计时，一度能看出作品不合自己心意，却说不清该改哪里。他用草图探索留白，后来做网站和应用，又去学字体、动画和交互。下文用编辑设计的导入按钮为例，试着把「交互有点钝」写成可以观察和验证的问题。

摄影让更多人能制作图像，同时把选取时机、构图和想给谁看留给拍摄者。Liu 用这个比喻讨论 AI 时代的工程工作：有更多可用的实现方式，就有机会选择更个人、更具体的目标。学设计和架子鼓也是他在演讲里给出的两个实际入口。

读完可以做什么
  • 把作品的受众和判断条件说清楚
  • 把模糊感受变成一个可观察的问题
  • 从陌生领域借一个评价角度，完成小规模试验
上手

重做一个自己每天会点的按钮

教学例：内部工具的「导入文件」按钮，等待时看起来和空闲一样。输入是一段操作录像、一份脱敏的 CSV 和另一个应用中类似流程的截图。输出仅提交一页交互样机和判断记录。

第 1 步

开一个观看任务

先看到使用者如何行动，再描述自己觉得哪里不顺。

展开可复制的提示词
通读导入录像。列出手指点击、系统开始处理、用户可见的变化和失败后的出口。指出能从视频确认的状态以及还没看到的情况。

完成标志　得到一张动作到可见结果的表。每条推测有明显标记，待补状态列出了需要哪种录像。

第 2 步

借一份参考作品

一张参考图可以解释视觉做法，重新命名问题才会影响设计。

展开可复制的提示词
对照参考应用。提取等待反馈、字号、留白和文字语义里与导入相关的两个做法。用自己的用户任务解释各自可能帮什么忙。

完成标志　能说出参考做法和真实痛点的对应关系。把纯偏好和需要验证的判断分开，留下一项待观察指标。

第 3 步

把想法变成两条操作路径

同一任务的两个方案给人明确的比较对象，也降低直接决定做法的风险。

展开可复制的提示词
输出两个最小交互样机。第一套禁用重复点击并显示进度，第二套把导入转成可后台继续的任务。用一次成功、一次失败和一次重复点击演示。

完成标志　重复点击、结果与恢复都有可见状态。文档写明哪套方案多了什么维护工作。

第 4 步

留出做选择的时刻

选择标准来自使用者的任务，演示方便比较而且不能替使用者决定。

展开可复制的提示词
以第一次导入的人和一天多次导入的人为角色，各自走完两套方案。记录在哪一步还能判断任务位置，筛出当前要试的一套，并写明不能确定的事。

完成标志　一页 decision note 中有选定方案、放弃方案的代价、下一轮要问的人与需要补的证据。

第 1 节

怎样衡量自己在尝试什么

Liu 把读者带回三个能在项目里问自己的问题。愿不愿意为作品负责，能不能指出结果好在哪里，有没有还想学的领域。

回看这一节 · 00:19:52 ↗

拥有作品落在三个决定上：愿意认领交付，能描述自己的偏好，以及敢去做一个超出现有经验的尝试。带着这三件事回看 Codex 示例，可以判断团队确实需要更多实施通道，还是需要先形成更清楚的方向。并行会话的数量能够影响尝试速度，能否说明为什么这套结果值得交出去，仍取决于负责人手里的证据。

第 2 节

摄影的例子怎样解释作品归属

相机让拍摄变容易，但摄影者仍得决定一个场景该从哪里看。项目交给 Agent 实现后，也可以记录这些改变成品的选择。

回看这一节 · 00:23:22 ↗

Liu 提到摄影改变了画家对如实再现的分工。对于电影导演，画面背后的时机、镜头和制作意图是作品的一部分。以导入按钮为例，用户真正关心哪个文件已经开始处理。即便 Agent 很快画好两个界面，决定它应该显示哪个动词、何时提醒失败，都要有人回到原始操作录像验证。

第 3 节

把“这个界面不对劲”说清楚

Liu 在艺术学校用草图摸索留白，做软件时又遇到字体、信息呈现和交互上的新问题。每学会一个更具体的词，就多一种办法说明自己希望改什么。

回看这一节 · 00:27:42 ↗

下文的导入按钮是编辑示例。标出界面里的隐含状态机能把“感觉软件不听话”写成用户能感知的路径。按钮接受输入后，可能是正在验证、正在导入、失败重试或完成。把每个状态的入口、出口及用户看见的反馈摆在一起，能找到缺了一处通知，或两条不同结果用了同一种提示。这个问题用单纯把按钮画圆或移动几像素处理不了。

第 4 节

回到以前没来得及学的东西

最好从一个能交出来的小结果开始。Liu 先想让自己的鼓和软件连起来，遇到的接口和工具才变成下一批具体要学的东西。

回看这一节 · 00:32:39 ↗

Liu 的架子鼓项目把乐器接入 MIDI，再借工具补 Ableton 的使用知识。用真实任务打开一个领域，可以判断下一项要掌握的是输入编码、工具设置，还是怎样听结果。这个方法也适用于给家人做工具：从对方真的会重复的动作开始，跟着操作，每一轮只放进一个自己暂时未知的知识点。

练习

用这一讲的方法做一次小练习

实作。挑一个你觉得不好用的界面，用三张截屏写出一份能指导 Agent 修改的反馈。

展开参考答案

给每张图标出具体症状、想改变的动作和可接受的样子。比如在窄屏上，先让主要操作露出来，再核对它是否挤走了必需信息。

实作。选一个暂停过的兴趣，定一个周末可以做完的作品。

展开参考答案

先写下能展示的终点和一件要自己学会的事。例如让 MIDI 鼓的一段输入显示为节拍反馈，并保留一次正确和一次错误触发的记录。

理解检查。运行许多 Agent 为什么无法单独说明项目的目标更有野心？

展开参考答案

并发量体现调用方式。项目的目标取决于人想交出什么作品、能否判断它是否做好，以及是否为结果负责。

理解检查。Liu 为什么会把看电影和试别人的应用列为工作的一部分？

展开参考答案

真实作品提供能比较的故事、界面和互动细节。这些经验帮团队说清要怎样改，而不必反复给出模糊指令。
