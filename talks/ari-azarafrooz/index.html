怎样用 KV Cache 观察 Agent 的异常行为？

从正常工作负载建立基线，给偏离打分，再用模型版本、复核结果和部署开销判断信号是否可用。

导读

一条分数偏高的告警，能告诉值班者多少

线上刚切了一个模型版本，异常监控图上的高分记录成片出现。值班者需要区分两件事，新版本改变了普通请求的分布，还是有一次具体的工作出现偏离。Ari Azarafrooz 在演讲中介绍一种额外的观察信号，利用推理时本来就存在的 KV 缓存，寻找偏离基线的计算片段。

看到偏离以后，还需要模型版本、任务类型和其他独立信息，才能知道下一步该找谁。下面的练习只使用模拟分数与预先贴好的标签，重点是分组、复核记录和上线门槛。原视频的案例说明怎样观察异常，生产中的授权和处置仍由已有系统负责。

读完可以做什么
  • 解释 KV 缓存作为推理内部观测和应用检查证据的区别。
  • 为合法更新设计独立基线与复核计划。
  • 用告警量、未告警抽样和额外开销决定是否扩大只读观察。
上手

从一张合成的值班表开始，演练如何复核异常分数

教学情境是一个文字助理升级推理引擎。所有分数、记录与业务标签都在纸上模拟。准备两组普通请求、一组事先标注的异常样本和一份完全独立的复核表。

第 1 步

给观察分数定好比较组

如果把合法的新旧工作负载混到一起，偏离分数可能主要反映版本变化。

展开可复制的提示词
写一张合成记录模板，字段限于匿名请求号、模型版本、请求类别、观察分数及人工标签。给每一组标上模型和任务。明确哪些记录参与建立基线、哪些只用于后续复核。

完成标志　值班者可以重现一个告警基于哪一组普通样本，以及该组有没有覆盖同类请求。

第 2 步

观察告警和未告警两侧

只看排在最前的异常，难以知道其他事件被漏掉多少。

展开可复制的提示词
在表格里为合成样本标明告警状态，分别统计告警中的正常项和未告警中的异常项。写清楚这两部分如何抽样，保留版本和类别列。准备至少一项合法变更来观察误报。

完成标志　三张表能复核，一组是高分告警，一组是未告警抽样，一组是专门检视的合法变更。

第 3 步

交给值班人员一份可读的情况摘要

事件的分数需要配上能确认的正常变化和缺少的凭据。

展开可复制的提示词
为一次模型升级后的高分记录写五行复核摘要。写请求类别、匹配的基线、升级时间、已看见的其他现象和后续验证。把分数结论标成观察，所有生产处置写为待批准。

完成标志　摘要没有为单一分数编造原因。值班者看得到可以先做的核对。

第 4 步

用实际成本决定是否扩大观察

推理状态的读取与传输也要占用服务资源。

展开可复制的提示词
为只读试点写一页决策表，记录复核时间、额外延迟、访问范围、告警积压和抽样覆盖。写下暂停条件，以及哪些条件满足后可扩大到下一个工作负载。

完成标志　表中有观察预算、责任人、停止点和允许的证据范围，未从模拟结论跳到生产授权。

导入

推理过程能提供哪些安全线索？

推理引擎会缓存每个 token 对应的键和值，生成后续 token 时可以复用。Ari Azarafrooz 提议再利用这些缓存数据，观察某段计算是否偏离已知的正常工作负载。

这类告警可以给运维人员和应用侧护栏增加一条线索。已有的输入输出检查、权限控制和工具调用策略仍负责各自的决策。告警指向的是一次需要解释的偏离，具体原因要结合模型版本、工作负载和其他证据判断。

基线

按工作负载建立基线，再对偏离评分

  1. 选一组有代表性的普通样本。先固定模型版本、信号提取方式和页面粒度。语音和文本等工作负载可以分别建立基线。
  2. 按同一方法计算偏离。为新的 KV 页或请求计算相对基线的异常分数，保留告警定位所需的时间和页索引。
  3. 核对告警含义。查看该请求属于哪类任务，是否发生数据分布变化，再判断是否进一步分类或人工复核。

训练过的异常观测只能说明对照结果。把语音、文本、短请求和长请求合在一起时，不同类型原本就会有不同分布。管理基线时可以给样本打上版本与任务类别，保持留出样本独立。拿同一类正常工作跨版本比较，才能定位告警到底来自流量变化还是版本变化。

讲者的语音案例用 72 段普通音频、4 种声音建立基线，并用 16 token 的页面粒度观察偏离。案例说明如何把检查定位到局部页面。每页多长、基线要覆盖多少差异，还需要按实际任务评估。

接入

在推理引擎或缓存层接入观察

讲者提出了几个可以接入的位置，包括推理引擎、缓存管理层以及能感知缓存状态的路由。引擎中的信号可以及时交给后续工具调用或策略检查。缓存层可以从保存的数据中筛选需要进一步调查的记录。

越靠近推理服务，越有机会在其他动作开始前得知异常。这个位置对资源与权限也提出要求。先测附加延迟和需要保存的信息，按已有的访问授权向值班人员展示摘要。缓存侧的观察可能更适合离线复盘，工作负载分类和异常发现仍需结合使用场景。

评估一个接入位置时，可以先记录能读到什么、每次读取的开销和告警到达时间。应用暴露给值班人员的证据应限定在核查所需范围，并按团队现有规则管理缓存和日志的访问。

验证

评估误报、版本漂移和数据搬运

讲者报告，文本案例排名最前的十条告警中，约七到八条对应值得处理的异常。这组数据描述的是被选中告警的复核结果。还需要有独立标注的未告警样本，才能估算漏报和整个工作负载中的准确性。

更换模型、微调模型或改变路由策略，都可能改变 KV 表示。讲者提出分别建立基线和研究共享表示两条思路。评估新版本时，可以重新检查普通样本分布、误报率和漏报率。缓存的读取、传输与转换也要计入延迟。

教学情境中，新版上线后的几条得分都越过了旧阈值，同时用户没有报告失败。快速复核先问新版是否已有独立普通样本，再看这种分布是否只出现在某种负载。没有新版对照时，可以把告警记录成待解释，保留申请复核所需的资料。另一条孤立的分数并没有跟随版本切换，也不能直接断定异常，要沿现有独立证据检查。

演讲展示的文本案例只汇报了排名靠前的少数告警。用它估计整个系统的准确率，会忽略未告警区和任务分布。准备扩大观察时，明确标注范围，保存完全独立的复核样本，配合常规权限和模型版本流程来决定是否继续。

上手

用合成异常分数做一次阈值复核

把手工构造的无量纲分数当作观察结果。A 至 E 使用同一基线，F 来自一次合法的模型版本切换。标签由演练者事先设定。按“分数大于或等于阈值就告警”的规则，用纸笔或电子表格计算即可。

  • A 0.12，普通请求。
  • B 0.18，普通请求。
  • C 0.41，少见但有效的长请求。
  • D 0.48，已标注的模拟异常。
  • E 0.73，已标注的模拟异常。
  • F 0.61，合法的模型版本切换。
  1. 先只用 A 至 E，比一比阈值 0.35 和 0.55 各会告警几条、误报几条、漏报几条。
  2. 再加入 F。记录分组错误引入的额外告警。给告警增加模型版本，并为新版安排独立的普通样本基线。
  3. 保留一份未参与选阈值的复核样本。对每个阈值记录告警量、漏报率和复核耗时，明确它对应的值班负担与覆盖范围。

演练只记录模拟告警。交付结果是一张能追溯分数、标签、触发条件和复核结论的表。

练习

核对三个判断

同一基线下，两组阈值分别会出现什么结果？

0.35 会告警 C、D、E，两条命中、一条误报、零条漏报。0.55 只会告警 E，一条命中、零条误报、一条漏报。选择取决于异常漏掉的代价和团队每天能复核的告警量。

合法升级后的请求 F 触发告警，先查什么？

比对该请求与基线对应的模型版本和工作负载。先复核新版普通样本，再确定阈值能否沿用。把其他风险证据和这次版本变化一起交给复核人员。

前十条告警中八条确实有意义，能算出漏报率吗？

还要有全部真实异常的数量，尤其是未告警样本里的异常。可抽取一批与选阈值无关的样本独立标注，再估算漏报率。
