搜索 Agent 为什么要付两笔钱？

Louis Walsh 用同一个查询比较六种检索结果格式。素材为 10 月 1 日 The AI Conference 官方完整录像，11 月 12 日 Expo 场次同题。

导读

为什么搜到正确答案，Agent 还是花了冤枉钱？

一个只需要确认比分的问题，可能带回十个网页。每个网页都在重复比分，还附带球队赛程、导航和分析。搜索服务对工具调用收费。页面一旦进入模型，它还会对模型的输入长度收费。Louis Walsh 的演讲让两笔账出现在同一张表里，接着用同一个查询比较六种返回方式。

他没有让读者只盯着便宜的搜索单价。对编程 Agent 来说，查到某个 SDK 的版本只是第一步。要是截断了兼容条件，Agent 还会去搜第二遍，或者写出在目标环境跑不起来的代码。练习里我们会给短事实与带限定条件的问题分别留样本，并算出每个正确答案的实际花费。

本页采用 2026 年 10 月 1 日 The AI Conference 的官方录像。11 月 12 日 AI Engineer CODE Summit Expo 议程登记了同一讲者、同一主题及同样的摘要。正文、截图和跳转时间均使用 10 月录像。

读完可以做什么
  • 在日志里区分搜索服务收费、证据读入费用和整条运行成本。
  • 用原文片段、跨页去重和限定条件核对，交付一份可回查的证据包。
  • 做一轮并排的检索评测，能复算每个正确答案的成本。
上手

四步做一次检索成本与答案质量对照

下面用一个教学任务贯穿四步。让 Agent 查一份公开 SDK 文档，判断现行版本能否设置某个参数。另选一条确实依赖套餐或版本限制的问题。冻结网页快照、问题集、预期答案和原网址，每个问题用相同模型各跑一次整页与摘录方案。操作用本地副本和模拟报价即可。

第 1 步

给每道题写一条能核对的正确条件

先记录两个风险不同的检索问题。单事实题可以核对版本号。限定题要同时保留参数名、哪一版开始支持、需要哪种套餐。把证据自身的日期和目标版本放在同一行，便于后面判断答对的是不是当前问题。

展开可复制的提示词
用给定的本地网页副本整理题库。每题输出问题、目标版本、正确答案、必须保留的限定条件和可回查位置。把按来源日期无法核定的题标为待确认。

完成标志　评审只看题卡和原网页就可以重判。两个方案用同一份题卡，题型和版本口径一致。

第 2 步

先跑整页基线，把两笔费用记开

同一轮任务可能调用三次搜索，每次返回不同长度的文本。保存工具调用数、每次返回的搜索结果 token、背景提示与输出 token。必要时还要记中间的摘要或重排费用。

展开可复制的提示词
用完整网页运行本地评测，输出一张逐题明细。每次调用记录来源、检索结果 token、调用次数，汇总模型输入输出、费率和失败重试。对于模拟费率，请以单独字段记录。

完成标志　任选一道题，能从明细复算任务成本。工具费与模型读取检索结果的费用可以分开查看。

第 3 步

用摘录覆盖同样的证据需求

短事实题常能压到一句。涉及例外的题需要连同上下文保留。对相同事实可去重，遇到两个来源给出不同适用版本，就保留分歧，交给下一层判断。

展开可复制的提示词
针对同一批问题，把整页改成 URL 加原文片段。标明原文位置、版本和关键限定条件。对重复片段选一份有足够证据的来源，列出没有去重的冲突。预算不够时，记录为什么扩读网页。

完成标志　每一个采信的结论都能定位到原文；限定题不能靠删掉例外换取更短的输出。

第 4 步

按每个正确答案的成本决定是否继续

如果摘录试验多漏几道题，只看平均 token 会得出错误的上线结论。按题型分别算正确数、失败原因、总费用和平均延迟。把缺证据的回答计入未通过。

展开可复制的提示词
按预先冻结的题卡复核两组结果。按题型输出样本数、正确数、总成本、每个正确答案成本、延迟和补读次数。给出两个实际失败样例，并指出相关的错误段落与可试的改动。

完成标志　读者能从明细复算正确数和成本。若开放调研明显掉分，可只对短事实题启用摘录方案。

第 1 节

一次搜索为什么有两笔账

回看本节 · 00:00 ↗

把“搜索成本”拆成两个量，才能定位故障。一种变化是便宜的搜索 API 让每次调用少花钱。另一种变化是同一个 API 返回的文档更短，模型少读内容。改片段格式通常作用于后者。即便调用次数没变，后一项也可能随长上下文快速上涨。

从业务追踪表可以先抽一条有代表性的运行。把每次搜索结果的 token 加起来，和系统提示、用户输入与其他工具结果分开。若日志只记录整个请求的 input tokens，下一轮就要加来源归属。

第 2 节

看同一个问题经过六种返回方式

回看本节 · 03:53 ↗

六种返回方式可以放进同一张表，但生成摘要那一行的数字最容易误导。约 300 token 表示下游看到的内容较短。上游小模型读过长输入，同样需要计费，也可能改写原话。把它和基于原文的摘录放到对照组里时，表里应该额外有“中间生成”一列。

第 3 节

从按页摘录走到跨页去重

回看本节 · 09:10 ↗

判断是否重复，要先认出实体、时间和主张。两个不同版本的 API 文档可能用了相同一句话，却分别适用于旧版与新版。如果把它们按字符串相似度合在一起，Agent 很容易把旧行为写给新用户。练习里应要求去重记录保存保留来源与被舍弃的理由。

再给系统留一条扩读路径。如果摘要没有出现套餐限制，而问题问的正是套餐，最直接的修正是读回包含限制条款的段落。把这次补读算进质量与成本，再判断自动摘录有多大可用范围。

第 4 节

把三组比例放回各自的比较口径

回看本节 · 12:23 ↗

95%、40% 和 30% 用的是三个比较对象。把它们连成一条下降曲线，会给人每一步在同一份任务上累加的错觉。做内部汇报时先给出基线与统计单位，再给数字。若想知道能否进一步降成本，应带上原始题集和执行条件重跑。

第 5 节

用任务总成本核算组件变化

回看本节 · 15:23 ↗

把公式写在题表旁边。每个正确答案的成本等于该组全部尝试的总费用除以正确题数。比如整页组花 1.20 美元，答对 8 道，单位成本为 0.15 美元。摘录组花 0.64 美元，只答对 4 道，单位成本则为 0.16 美元。这个教学例里账单变小了，但每获取一个可用的结果，需要付的钱反而更多。

复算讲者的 API 成本示例时，两张表里的搜索费率也变了，开头示例一次 0.010 美元，后面 0.007 美元。后图上方仍有沿用前图的比例标注，表底 token 合计也和新分项不一致。本手册采用可加总的美元分项，课堂对照时应固定所用费率。

第 6 节

问答里的适用范围

回看本节 · 17:22 ↗

从观众问答可以抽出一个实际投放策略。对于查单一事实的路由，先试短摘录并检查引用。如果问题要求总结一家公司的不同业务、历史变化、政策例外，则允许扩读，并单独评测这类请求的召回。这样的策略可以用已有题库逐步收敛，先约定何时扩读，再看模型如何触发。

练习

核对自己的检索账单

如果检索结果更短但重试次数更多，怎样判断是否节省？

展开参考答案

计算整个题集全部尝试的费用，包括失败和补读，再除以正确题数。短结果可能只是把花费挪到了重试。

两个网页都写同一句话，但一个谈旧版本，一个谈新版本，怎样处理？

展开参考答案

先核对版本和生效时间。若条件不同，就保留两条带出处的证据，再以用户要求的版本判断。

95%、40%、30% 可以相加吗？

展开参考答案

三者分别对应整页内容、逐页摘录和整条任务。分别记录基线，再对自己的任务重跑。
