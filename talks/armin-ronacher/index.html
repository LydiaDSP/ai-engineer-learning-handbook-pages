导读

给 Agent 留一张能回来继续用的工作台

Armin Ronacher 借工匠工作室来讲他想怎样写软件。机床或 3D 打印扩大了一个人能完成的工件，留下的工件仍然需要人理解。类似地，他观察到 Pi 核心工具大体稳定，会话却随模型变化出现了不同的 Bash 行为，他不必像早先一样频繁打断 Agent。

本篇从三个可观察的决定入手：删不删一项工具，在哪个节点让人介入，以及一项工作停下之后怎样恢复。Ronacher 还讲到 TAR 归档互操作的麻烦。写实现更快以后，共同格式和维护成本要早点进入决策。

读完可以做什么
  • 给重复使用的工具找一个可以比较的样本
  • 设置能发现维护风险的人类检查点
  • 让长任务在关闭进程后仍然读得到下一步
上手

试着移掉一项自己舍不得关的工具

教学例：一条批量材料整理任务，每次都调用一个专门插件。输入是九份脱敏说明文件、两组旧运行记录和一个确定的产物清单。练习以本地工作目录为界。

第 1 步

定下有意义的比较

先确认工具替团队背着什么，再决定观察哪些结果。

展开可复制的提示词
从旧运行记录提取插件实际完成的动作、输入和验收点。把失败后需要人接管的动作单列出来。给本次试验准备固定样本。

完成标志　给出旧版输出清单和已知异常，知道工具负责筛选、状态还是质量检查。

第 2 步

让模型走两条路线

在同样的输入上比较，才知道模型变强后工具还有哪些作用。

展开可复制的提示词
确保输入和判定规则相同，分别跑有插件和使用基础文件工具的路线。保留原始记录、退出状态、人工接手次数及产物。记录每条路线第一次发生偏差的位置。

完成标志　两组输出可以逐条核对，其中失败项能复跑。发现无关环境差异时先归为不可比较。

第 3 步

加一个人能接手的节点

等最终提交才审，可能已经错过结构选择。

展开可复制的提示词
在首次分析之后暂停。展示将修改的文件、依赖、兼容条件和不确定点。保留计划和已检查的输入。等待人明确选择后继续执行。

完成标志　另一个同事能在三分钟内找到未决事项，知道说“继续”之后系统会改哪一部分。

第 4 步

重启并检查恢复后的差异

长任务要通过保存可用状态来抵抗中断。

展开可复制的提示词
中途退出进程。用新的会话从检查点恢复，先确认输入版本、已完成条目和下一项。运行到底后对照从头跑的输出，说明复跑的动作。

完成标志　最终交付清单一致，已经有提交的动作不会重复执行。遇到来源版本变化时会暂停核对。

第 1 节

模型进步之后，工具该留下什么

Ronacher 从自己的 Pi 会话出发。读这些曲线时，要把模型自己学会的动作与运行环境提供的能力同时记下来。

回看这一节 · 00:40:04 ↗

旧的操作框架可能包含三个东西：模型当时不善于做的动作、日常依然需要的可观察与恢复能力，以及团队规定的权限边界。模型更强时，前一种更适合拿出来重试，后两种需要看工程结果。Ronacher 使用 Pi 和 Auto Research 的经验适合启发对自己的录制历史抽检，尤其在更换模型后观察下一代是否还能妥善控制成本、恢复任务和指出自己做过什么。

第 2 节

把人能看懂的那部分留在流程里

提交量上升后，Ronacher 回看会话，找一个稳定的介入点。他通常在任务进行到约 70%、进入验证之前，让 Agent 写一份简短汇报，并出一页便于阅读的 HTML。

回看这一节 · 00:44:46 ↗

Ronacher 稿里的项目与提交趋势不能直接作为质量统计。并行增加时，人还要消化方案、决策和长久维护的影响。接口选择是另一种可尝试的检查点。例如，团队可以在 Agent 第一次需要决定是否复用现有库时，先请它写份简报。简报同时列出候选、既有约定和待问问题，能减少写完整套实现后再返工。

第 3 节

共同格式和协作要继续有人管

写出一个自己的实现越来越容易。碰到用户要交换文件、升级依赖的地方，新的实现还得共享一份清楚的规则。

回看这一节 · 00:51:16 ↗

TAR 的例子说明一个共同名字不保证实现细节一致。某种归档在自己工具里解得开，交给另一团队的程序却可能读出不同的目录关系或元数据。给工具增加一个格式前，先查规范和现有库；在代表性样本里保留异构实现交叉读取的结果。如果团队考虑 fork，再决定怎么跟上游交流和承担后续更新。

第 4 节

让长任务能回来，也能自己编排小流程

可以从三个中断点检验运行环境。进程退出以后能否继续，批量读取时能否只留相关结果，卡住的决定能否回到人手里。

回看这一节 · 00:54:53 ↗

长任务需要持久记录已完成的步骤和依据。讲者以批量处理客服请求为例，用分类器决定每条请求交给 Agent，还是向客户补问。挂起前可以写出在哪个提交上处理到了第几组输入、还有没有没交接的操作，以及什么时候必须重新读取源文件。恢复时检查版本，再继续下一步。演讲中将部分筛选与工具调用放入 JavaScript 的办法也有类似的审查需要：批处理省掉很多上下文，但被筛掉的条目最好有计数、条件和可回查样例。

练习

用这一讲的方法做一次小练习

实作。选一个会跑 30 分钟以上的 Agent 任务，写下中间保存点和人工介入点。

展开参考答案

例如处理一批迁移后，每完成一个模块就存进度与验证结果。发现跨模块的接口不一致时暂停，交回差异、证据与两个可选方向，等待人选定。

实作。比较自己实现一个文件格式和在上游修兼容问题的代价。

展开参考答案

用几份真实文件测试读写与往返，再列出要长期同步的差异。若涉及多个工具共享规则，把复现和最小补丁先带给上游讨论。

理解检查。模型升代后，为什么还要复查旧插件是否需要？

展开参考答案

旧插件可能只是替早期模型弥补规划能力。用代表场景比较有无插件时的结果、恢复表现和人工介入次数，再决定如何保留。

理解检查。让 Agent 在代码里批量调用工具，用户看见的上下文有什么变化？

展开参考答案

循环可以就地筛选或压缩原始结果。后续会话可以先查看精选结果，并从记录里追溯需要核对的调用。
