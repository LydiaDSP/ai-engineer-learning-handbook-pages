学习手册 第二天 10 / Jeffrey Pinner

Agent 搜到东西以后，怎样知道它找对了？

把搜索放进一张需要交付的事实表，拆开新鲜度、来源覆盖和上下文成本。

Exa CTO约 11 分钟演讲中文导读与讲解 · Lila
Agent 搜索评测上下文
导读

搜索结果看起来都相关，表格为什么还是交不了？

一个 Agent 从发布说明里找到了项目名称，又把旧价格和新版本号拼到同一行。每条摘录单独看都像答案，交付物却站不住。Jeffrey Pinner 把这类错误当作搜索系统的测试对象。Exa 的 Atlas 先要求找到符合条件的实体，再把同一个实体的多个字段补齐，任何一项错了，整行就不能交。

这场演讲可以按一条实际链路读。模型回忆出一个名字，查询去索引里找候选，系统从候选网页提取证据，最后 Agent 写表。模型缺新事实、文档根本没被索引、摘录丢了脚注，都会让表格出现空洞。能定位第一处出了什么问题，才知道下一步该调整搜索，还是该补证据。

读完可以做什么
  • 给一张研究表定义整行可交付的条件。
  • 把新鲜度、覆盖、摘录和推理错误分别记下来。
  • 用同一批任务同时比较准确性、证据完整性和读入成本。
上手

用一张小表测试 Agent 搜索

挑三个你熟悉的开源项目，从可公开访问的一手资料确认许可证、版本和维护状态。记录核验日期，保留一个故意缺少可靠说明的字段。它会检验 Agent 遇到未知时怎么报告。

第 1 步

先准备一份答案表

如果任务口径没固定，同一条旧版本可能在两轮中被定成不同结果。

展开可复制的提示词
请把目标拆成项目身份、许可证、截至指定日期的最新稳定版本、能说明维护状态的证据。每个字段列可接受的一手来源类型和截点，暂时不要查询答案。

完成标志　维护状态有自己的判据。发布候选版与稳定版明确区分。

第 2 步

跑一次闭卷和一次带检索

固定模型和输出格式，才能看出加工具解决了什么。

展开可复制的提示词
先只依据模型当前知识填表，标出不确定的项。再用公开检索重做同样的表，为每个填写值附一手链接、日期和短证据。两次输出分别保存。

完成标志　两组输入完全相同，闭卷没有被上一轮答案污染。

第 3 步

找到第一处破坏交付的错误

查询命中以后还可能拿错页面范围。

展开可复制的提示词
按实体、字段、版本与证据逐项比对。把每个错误归到候选没找到、来源访问不到、摘录选错、理解出错或要求本身不清，并写出当时实际拿到的证据。

完成标志　一个错值最多需要修一处首因。没有可靠依据的地方显示未知。

第 4 步

比较全文和定向摘录

保存限定条件比一味缩短上下文优先。

展开可复制的提示词
用同一批原始页面分别返回完整正文和按问题抽取的片段。比较整行通过数、支持了多少字段、输入 token，并列出两种方式各自漏掉的一条限定条件。

完成标志　页面、题目和模型一致；差异能追到一个摘录或脚注。

第 1 节

模型缺的是哪一类事实

Exa 的 Jeffrey Pinner 把问题放在具体任务里。模型可以整理一张表，但表里的公司、日期、版本和价格，仍要从模型训练完成之后变化的世界里找。

回看这一节 · 02:59:08 ↗

研究任务经常混着两种时钟。模型知识截至训练时点，演讲里的资料又各有发布日期。同一个项目同时存在维护分支和稳定版时，较新的一条新闻也可能不符合问题。做产品表时，把截至哪天和适用对象写进查询，再让 Agent 为每个字段保留可以独立核验的页面。

第 2 节

用 Atlas 看完整任务是否做成

表格任务适合看错误如何累积。某个实体找对了并不代表这一行可交付，后面填的几个字段也需要核对。

回看这一节 · 03:02:31 ↗

教学例。假设要调查项目甲的稳定版本、许可证和维护状态。官方发布页写稳定版为 v2.3，预览公告写 v3.0，仓库许可证只说明当前默认分支采用 MIT。可以交付的记录是稳定版 v2.3，许可证需要找到对应标签下的文件，维护状态截至核验日仍待查。这样一行暂时不能算完整通过，读者却知道缺的证据是什么。

第 3 节

找得到、拿得到，也要读得动

一次研究要跨过多个环节。查询表达清楚，仍可能碰到索引覆盖不到的来源。结果拿回来了，还得控制 Agent 为提取一条信息读多少上下文。

回看这一节 · 03:04:22 ↗

有些检索失败来自查询太宽，例如只搜项目名称。还有些失败出在最后一米，搜索返回了正确的定价页，摘录却留下月付金额，丢了年付换算的说明。两种错误会让同一个单元格不准确，但前一种要调整发现策略，后一种要保留正文、页脚和相邻表头的关系。

第 4 节

查询相关的摘录怎样影响结果

Exa 把检索与摘录拆开。前一步发现可能有用的来源，后一步根据问题选正文，再把外部信息交给 Agent。

回看这一节 · 03:07:01 ↗

Pinner 给出三项 Atlas 整行正确率。闭卷约 9%，关键词检索约 28%，语义摘录与扩充数据约 56%。摘录、索引范围和扩充数据同时参与，图中的变化无法单独归到某一项。他另报告约 28% 的成本下降，这个数字衡量的是成本。自己复测时可以先固定候选页面，只换给模型的证据长度，判断质量与成本是否还呈现同样变化。

练习

用这一讲的方法做一次小练习

设计一个可检查的搜索小基准，为十个开源项目补齐许可证、最新版和维护状态。怎样计分？

展开参考答案

先为每项建立带日期的标准答案和原始出处。只有所需字段均正确的一行才记为通过，同时单列错版本、错对象和无证据的字段。用同一批题比较闭卷与有检索的配置。

Agent 找到正确的页面但把价格抄成旧价格，你会先改哪个环节？

展开参考答案

对照查询、页面有效日期和返回的证据片段。旧价格所在的段落被摘录时，应改摘录或排序。来源本身过期时，要添加更新来源并约束时间。

什么情况下应保留更长的摘录？

展开参考答案

当答案依赖脚注、适用条件、统计口径或相邻表头时，保留足够的上下文，把摘录和原网址一起留给 Agent 回查。

比较原始 HTML 与定向摘录时，除了最终正确率还要记录什么？

展开参考答案

保持模型、题集和时间窗口相同。另记读入 token、检索次数和可回查引用覆盖率。摘录便宜但遗漏关键限定条件时，报告正确率与成本之间的取舍。
