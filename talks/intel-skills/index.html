你的 Skill 到底给模型增加了什么？

先用有无 Skill 的对照量整项任务，再把指令拆成可提问的知识点，找出哪些细节值得留在上下文里。

导入

你想检验模型多知道了什么，还是检验它会不会按流程做？

Nikolay Petrov 把 Skill 的作用分成两类。补充知识的 Skill 告诉模型它原来可能不知道的东西，例如项目约定的字段名、阈值或异常处理规则。引导流程的 Skill 帮 Agent 稳定地按团队希望的顺序工作，例如先预览，再等待确认，最后执行。

这场分享主要测第一类。某条指令即使没有增加新知识，也可能发挥引导作用。准备删减之前，先写清这条指令是给模型提供资料，还是提醒它在特定条件下采取行动。

上手

选一个 Skill，跑一次有无对照

选一个你实际使用的 Skill，再选三到五项有明确验收标准的任务。手边没有样本时，可以从下面的测试导出练习开始。这是模拟任务，可以直接在聊天中对照输出，不需要连接真实系统。

  1. 定义任务和标准。从 Skill 中选三个可以独立评分的知识点，并写一个会同时用到它们的真实任务样式。预先写好预期答案和通过条件。
  2. 每题开两个新会话。保持模型、题目、输入和工具权限一致。A 组没有 Skill，B 组加载 Skill。若是在聊天里模拟加载，可只给 B 组附 Skill 正文。两组题目都不带答案。
  3. 记录差异。每题记录 A/B 原答、是否通过、对应条目和备注。界面提供 token 或耗时数据时，连同这些数据一起记录。结果不稳定的题多跑几次。
  4. 精简后复跑。只改优先级最高的一条。用相同设置对照原版和精简版，再加一条此前没见过的任务。核对关键结果和执行步骤是否仍然通过。

模拟 Skill · 交付测试报告

只在 B 组提供这三条约定：交付物用 CSV，以 UTF-8 编码，负责人字段为 owner_team。按列名 case_id,result,owner_team 导出。

对两组都提问：请把“用例 T-01，通过，由测试组负责”整理成团队可交付的一行测试报告。给出文件格式、编码、表头和数据行。不确定的团队约定标为“未知”。

展开参考输出和评分

格式为 CSV，编码为 UTF-8，表头为 case_id,result,owner_team。数据行可以写为 T-01,通过,测试组。分别检查格式、编码、列名与整项任务。A 组能凭常识选中 CSV，也可能猜到 UTF-8。团队专用列名要按约定精确评分，不能把任意类似名称算作通过。

完成标准：拿得出同题两组输出、逐项评分记录和一条删改决定，并能指给别人看支持这项决定的任务结果。

任务对照

整项任务先跑一遍，看看 Skill 有没有带来变化

Petrov 用五项任务举例。没有 Skill 时模型完成三项，加载后完成五项。这个对照告诉我们，在给定模型和题组下，加载 Skill 后多完成了两项。还可以并排记下 token 和耗时，检查增益是否伴随额外成本。

任务通过规则尽量写成能直接核对的结果。例如检查输出能否被解析、列名是否准确、遇到缺失信息是否停下来提问。整体跑分能显示成绩变了多少，逐条提问能进一步定位哪些说明可能带来了变化。

逐条测量

每个可验证的知识点配一题，按四种结果来读

讲者的做法是把一项 Skill 拆成约 25 到 30 个可以独立提问的知识点，每个点配一个问题和一个预期答案。小规模试跑可以先选三到五点。题目不要嵌入答案。要测模型自身掌握的知识，可以关闭检索工具。要测实际工作环境，两组就都保留该环境里的工具。

精确字段可以用程序直接判。开放题先写评分规则，再请人工、另一个模型家族或多位裁判比较。逐条评测的作用是告诉你应该先查哪几句，修改是否有效还得看任务结果。

评分

理解“应按规范导出”，和说出确切字段，是两种能力

宽松评分看基本概念和意图。严格评分核对实际执行需要的键名、参数、值和操作顺序。比如“输出负责人字段”可以通过概念题，导出流程要求的 owner_team 要逐字符核对。一个字段写错就会导致下游读不进去时，严格评分更接近真实验收。

在讲者展示的 Opus 5.5 未加载 Skill 的基线中，按宽松的概念评分约为 70%，按严格的细节评分约为 22%。他还提到，覆盖 29 个 Skill 的那次实验，Sonnet 和 Haiku 的调用费用约为 14 美元。两组数字各自对应演讲展示的样本、模型和设置。

复测

删掉一条之后，回到会用到它的真实任务

从“对 → 对”里挑出一条删减候选，留下原版。用相同任务对照原版和精简版，最好再加一条新场景。检查整体结果、具体字段和要求执行的动作。质量维持住，再核对精简后是否省下上下文或调用开销。

同一条说明对两个模型的价值会不同。有的模型本来就懂基本概念，仍需要专门的参数才能完成工作。换模型、工具或者团队约定时，把相关任务重新跑一遍，再更新结论。
